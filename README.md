# RainPredict — Weather-Based Rainfall Prediction Website

This is a Flask website that embeds the global rainfall prediction model.

## How it works

1. Loads the combined rainfall + NASA weather dataset.
2. Cleans `-999`/`-9999` missing-value placeholders.
3. Sorts each district chronologically.
4. Creates next-day rainfall targets.
5. Trains a global Logistic Regression rain/no-rain model.
6. Trains a global Logistic Regression heavy-rain model (>20 mm).
7. Fits a Weibull distribution to positive rainfall.
8. Exposes `/api/predict`.
9. The website sends a selected district to the API and displays the prediction.

## Important academic limitation

The current dataset contains a short time period, so this should be presented as an academic prototype rather than a production weather forecasting system. More years of daily data would substantially improve the model.

## Interactive district map

The home page now shows an interactive Leaflet map of India with district boundaries.

- **Select a district** by searching (the search box shows matches) or by clicking its outline on the map. The map centres on it and outlines it in an animated cyan line.
- **Predict Next Day** calls the existing `/api/predict` endpoint. The forecast card, probability ring, cloud and rain-streak intensity, and threshold chart are all filled from that response. Nothing is estimated in the browser.
- **Weather animation** is illustrative only. Probability tiers: below 10% clear, 10–29% light, 30–59% moderate, 60–79% heavy, 80% and above very heavy. It is not radar or satellite data. Animation respects `prefers-reduced-motion` and pauses off-screen or in background tabs.
- **Charts**: the global Weibull density (fitted parameters from `/api/info`), threshold exceedance for the forecast, and the last 60 days of observed IMD rainfall for the selected district.

### New endpoints (additive; model unchanged)

- `GET /api/districts`: districts with state and coordinates.
- `GET /api/history?district=&state=&days=`: real observed daily rainfall.
- `POST /api/predict` accepts an optional `state` to disambiguate names. Existing requests without it still work.

### Boundary data

`static/data/india_districts.geojson` is generated by `scripts/build_district_boundaries.py` from the MIT-licensed
[datta07/INDIAN-SHAPEFILES](https://github.com/datta07/INDIAN-SHAPEFILES) `INDIA_DISTRICTS.geojson`. The script matches all 728 dataset districts to polygons by name (with state aliases and fuzzy matching). Each match is checked against the dataset's coordinates, with a spatial fallback. The match table is in `scripts/boundary_match_report.csv`. Limitations:

- The boundary source is not the latest administrative vintage. Some dataset districts (for example, those created in 2020–2025) are matched to the closest polygon in that source, and the report marks these matches.
- Polygons are simplified (~900 m) for web use.
- Any district without a usable polygon is shown as a coordinate marker. No boundary is invented.
- Basemap: the public `tile.openstreetmap.org` server returns HTTP 403 ("Access blocked") to app traffic under its tile usage policy, so the map uses CARTO's dark basemap, which is built on OpenStreetMap data. It needs internet access from the viewer's browser. To change providers, edit `TILE_URL` and `ATTRIBUTION` in `static/js/district-map.js`. For production traffic, use a commercial tile provider or your own tile server.
